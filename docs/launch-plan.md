# 发布后改进计划：让人看懂、试得到、对得上需求（2026-11-11）

> 背景：v0.1 部署上线、演示站 demo.hikariming.com 开放后，GitHub 上有人看，但没人试。
> 这份计划分三条线：一、让人试得到（哇时刻）；二、让人看得懂（README 与口号）；三、确认需求对不对得上（找到对的人、听他们说）。

## 0. 诊断

| 现象 | 原因 | 证据 |
|---|---|---|
| 看了不试 | **演示站试不到 AI**：没接模型；网页版应用按设计不带 AI；访客进来是管理后台 | `deploy/demo/demo.env` 没有模型；`web/src/pages/app-web.tsx`「没有 AI」；演示模式禁止加模型接入 |
| 看了记不住 | 第一句讲的是流程（接入 → 组装 → 审核 → 下发），没讲谁、在什么场景下得到什么 | README 第一屏 |
| 可能不是目标用户 | GitHub 上看 DSH 的多是个人开发者，没有 ERP、不管审批；真正有痛点的是企业 IT / AI 负责人，他们不刷 GitHub | 推断，要靠第三条线验证 |
| 真体验门槛高 | 完整体验要「部署 dsh-ee + 装 DSH + 接入」三步 | 快速开始 |

结论：先解决「试得到」，再改「看得懂」，然后带着能用的演示去找对的人验证需求。顺序不能反：没有演示可试，去哪里发都一样平淡。

## 一、让人试得到（哇时刻）

目标：**访客 30 秒内看到「员工问一句话 → AI 查了公司系统、引了公司制度、给出答案」**，不用装任何东西。

### 1.1 演示站首页改成「以员工身份体验」（必做）

- 演示模式下，登录页第一屏换成 4 张场景卡片，每张一个演示员工和一个问题：
  - 周航（客户经理）·「客户拜访简报」：「华东精密制造下周要续约，我该注意什么？」
  - 陈一（费用会计）·「出差报销助手」：「本月报销单里有没有异常？」
  - 郑小雨（新员工）·「新人入职助手」：「我第一周要做什么？VPN 连不上怎么办？」
  - 吴敏（HRBP）·「团建报名」：自带数据表的员工自建应用
- 点卡片 → 以该员工身份登录 → 直接打开这个应用。管理员入口放到下面，作为第二步：「看看管理员怎么审核、授权、审计」。
- 演示员工密码导入时随机生成，要改成演示模式下可一键登录（只在 `DSH_EE_DEMO_MODE=1` 时生效）。

### 1.2 让访客看到 AI 回答（已定：C + 代码生成的介绍视频）

**C. 用自己的 DSH 接演示站。** 已装 DSH 的访客运行 `setup.sh` 接演示站，用自己的模型 key，用演示站的应用、知识库和示例连接。

- 先验证：演示模式下设备码接入能不能走完；演示站没接模型时，DSH 能不能继续用访客自己的 key；示例连接（`/demo/*`，走回环地址）从访客电脑经 MCP 网关调用是否正常。
- 走通后，在登录页场景卡片下面和 README 里各放一段「已经装了 DSH？三步接上演示站」。
- 演示员工令牌随重置失效，说明里要写清楚「重置后重新接入」。

**视频：用代码生成 30～40 秒的项目介绍，放在 README 第一屏和演示站登录页。**

- 工具：Remotion（React 写画面，直接渲染 MP4），放在仓库里单独的 `promo/` 目录，不进主构建。画面里的 dsh-ee 界面用 Playwright 从演示站截真图；DSH 对话画面用动画模拟，角落标「示意」。
- 产物：`promo/out/intro.mp4`（中文、英文各一版）和一个压缩到 5 MB 以内的 GIF（`docs/images/intro*.gif`）。README 用 GIF 保证一定能显示；MP4 由你在 GitHub 网页上拖进 README 编辑框，换成 user-attachments 链接后可以直接播放。
- 分镜（约 36 秒）：

| 时间 | 画面 | 字幕 |
|---|---|---|
| 0～4 秒 | 空白对话框，员工问「华东精密制造下周续约，我要注意什么？」，AI 答「我不知道你们的客户」 | 老板让全员用 AI，可 AI 不认识你的公司 |
| 4～12 秒 | 同一个问题在 DSH 里用 `/customer-brief`：依次出现「查 CRM · 客户详情」「检索 · 产品资料」卡片，答案带出处（21 天后到期、75 天没拜访、续约 9 折） | 接上 dsh-ee，AI 查公司系统、按公司制度回答 |
| 12～20 秒 | 管理后台真图：ERP / CRM / 知识库 → 组装成微应用 → 审核 → 按部门授权 → 下发到员工 | 接入、组装、审核、下发，都在你自己的服务器上 |
| 20～28 秒 | 写操作弹审批卡；审计日志滚动；一键下架 | 凭据不出服务器，每次调用都有记录 |
| 28～33 秒 | 架构图动画：中间 dsh-ee，四周员工电脑上的 DSH | 推理在员工本机，dsh-ee 只负责备好、管住 |
| 33～36 秒 | 口号 + demo.hikariming.com + GitHub 地址 | 让每位员工的 DSH 都认识你的公司 |

方案 A（演示站自己跑 AI 对话）暂不做，等两周后复盘再看。

### 1.3 页面顶上的提示改成引导

演示站顶部的横条现在只提示「会重置」，改成同时带一句下一步：「你现在是周航，试试问 …… / 切换身份 / 看管理员视角」。

## 二、让人看得懂（README 与口号）

### 2.1 口号

不用「把整个企业放在一个 Harness 里运行」：它和架构说反了（推理在每个人本机，不在一个中心），也说得太满，还把最大的卖点「管得住」丢了。

把方向倒过来。已定：

**让每位员工的 DSH 都认识你的公司** / *Your company, inside every employee's Harness*

副标题统一为：数据和凭据留在你自己的服务器，经过审核授权才送到员工手里，每次调用都可审计。

### 2.2 README 第一屏重排（中英文两版同步）

1. 口号 + 副标题
2. **介绍视频的 GIF**（来自 1.2）
3. 一个醒目的按钮：「在线试一下，不用装任何东西 →」直接进 1.1 的场景卡片
4. **三个场景**，每个一句话 + 一行截图：销售问续约风险、会计查异常报销、新员工问入职
5. **适合谁 / 不适合谁**：适合「已经或准备让员工用 DeepSeek / DSH、又担心数据和权限的 50～2000 人公司」；不适合「个人使用」「只想要一个聊天框」
6. 现有的对比表、功能、架构、快速开始往下放

### 2.3 GitHub 仓库页

- About 描述换成新口号，加 topics：`deepseek`、`mcp`、`enterprise-ai`、`self-hosted`、`ai-governance`、`knowledge-base`
- 社交预览图（Settings → Social preview）用新口号 + 场景截图

## 三、确认需求对得上

### 3.1 想清楚第一批用户是谁

先假设：**中小企业里负责「让员工用上 AI」的 IT / AI 负责人**。他们的痛点是：老板要求全员用 AI，但数据不能出去、权限管不住、事后查不到。

要验证的三个问题：

1. 他们现在怎么让员工用 AI？（直接用网页版？买了企业版？完全禁止？）
2. 最先想接的系统是什么？是 ERP / CRM，还是只想要知识库问答？
3. 「员工必须装 DSH」是门槛还是加分项？

第 3 条最关键：如果答案是门槛，网页版带 AI（方案 A）就不只是演示，而是产品方向，需要重新讨论「不自己跑 AI」的决定。

### 3.2 怎么问

- GitHub Discussions 开一个置顶帖：「你们公司现在怎么让员工用 AI？」，README 链过去
- 演示站登录页底部放一行：「你们公司想先接哪个系统？」→ 链到 Discussions 或一个两题的问卷
- 主动找 5～10 个人聊（身边的 IT 负责人、DSH 社区里问企业部署的人），每次 20 分钟，按上面三个问题记录

### 3.3 看数据

- Cloudflare 后台看演示站访问量
- 演示站加最少量的统计（只在演示模式下，存在本机日志）：场景卡片点击、应用打开、DSH 接入次数。不收集个人信息。
- 两周后看：访客里有多少人点了场景卡片、有多少人走完 DSH 接入

## 六、发布前自动冒烟（2026-11-11 补充）

发布前至少跑一遍 `e2e/tests/29-release-smoke.mjs`（已进 CI 的 e2e job），它检查一个全新部署最先被用户碰到的三个入口：

- `GET /healthz` → 200 且 `status=ok`；
- `GET /setup.sh` / `GET /setup.ps1` → 200、正文完整、包含「dsh-ee 接入脚本」；
- 管理员发布接入插件后，`GET /api/connect` 给出 `tarball_url`，下载的 tarball 是 gzip 且可解析。

本地跑法（需要 TiDB/Chrome，见 `e2e/README.md`）：

```sh
cd e2e
E2E_MANAGED=1 E2E_BIN=../dist/dsh-ee E2E_DSN='root:@tcp(127.0.0.1:4000)/' \
  ADMIN_PW=... CHROME=/path/to/chrome node run.mjs 29-release-smoke
```

这不是产品行为测试，而是发布前的最低可运行性检查；如果它红了，先别发版。
